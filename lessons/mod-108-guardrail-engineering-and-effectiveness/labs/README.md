# Labs for mod-108-guardrail-engineering-and-effectiveness (Guardrail Engineering and Effectiveness Measurement)

Three 45-minute guided drills. Each builds one atomic output-shape authoring skill the exercises assume, on a fixed running system (`HelpDesk`, a customer-support RAG assistant for a mid-size B2B SaaS company; FastAPI + LangGraph + LangChain retriever over an internal pgvector store; two production tool calls `escalate_ticket` and `lookup_account`; strict data-residency posture). The labs do not duplicate the module's exercises — the exercises run the real tools (NeMo Guardrails + Guardrails AI + custom middleware; Llama Guard + ShieldGemma; Presidio; the mod-104 adversarial and legitimate sets; real vendor documentation) against the reader's own running system; the labs drill the output shapes those artefacts rely on against the fixed `HelpDesk` system with fabricated-but-plausible numbers.

- [`lab-01-slot-coverage-table-authoring-drill.md`](lab-01-slot-coverage-table-authoring-drill.md) — 45 minutes. Author the chapter-01 slot × attack-class coverage artefact end-to-end on `HelpDesk`: the framework-version header (OWASP LLM Top 10 v2025, MITRE ATLAS, Google SAIF), the five-slot specification with named responsibility / failure mode / mechanism candidate, the coverage table where every cell is a framework code or `—`, the scenario-slot matrix across the five fabricated harm-model rows, the composition walk-through for three scenarios (defence-in-depth sequence; second-mechanism proposal; silent-SPOF anti-pattern most plausible for HelpDesk's streaming endpoint), and the register-handoff note that queues chapter-05 measurement without pre-crediting residual. Chapter 01 skill feeding exercise 01 and every downstream exercise.
- [`lab-02-fp-fn-report-authoring-drill.md`](lab-02-fp-fn-report-authoring-drill.md) — 45 minutes. Author the chapter-05 §"Skeleton (per surface)" one-page product-manager report on fabricated measurement numbers against `HelpDesk`: surface identifier + mod-104 set versions, top-three FPs with example legitimate payloads + volume estimates, top-three FNs with example adversarial payloads + harm-model linkage + mod-109 monitor status, coverage summary across OWASP LLM Top 10 banded fully / partially / uncovered, cost roll-up (compute + operational + licence) in register currency, latency roll-up at p50 / p95 with serial vs. parallel at the output slot, trend arrows vs. the previous run, and an explicit numbered decisions-requested list (accept-FP / accept-FN / sign-off-spend / agree-latency / agree-scope). Chapter 05 skill feeding exercise 05 and the register updates that follow.
- [`lab-03-build-vs-buy-matrix-and-decision-record-drill.md`](lab-03-build-vs-buy-matrix-and-decision-record-drill.md) — 45 minutes. Author the chapter-06 four build-vs-buy artefacts on fabricated vendor profiles and the lab-02 in-house measurement numbers against `HelpDesk`: the twelve-axis matrix across the in-house stack and five fabricated vendors (Lakera Guard, Arthur AI, Robust Intelligence / Cisco AI Defense, Calypso AI, HiddenLayer) with every cell a number or a defended bounded rating, the two summary numbers per option (total residual-risk delta vs. in-house baseline; total three-year TCO with exit cost) with Lakera disqualified on residency, the signed decision record naming driving axes + trigger events + a compose scenario considered-and-rejected with named seam ownership, and the self-contained measurement contract to `ai-eval-engineer` (L30) with slot ids / control-instance versions / register linkage / explicit "what we do not supply" block. Chapter 06 skill feeding exercise 06 and the cross-track handoff to the eval engineer.

Run the labs in order — lab 02 uses the slot assignment from lab 01's mechanism table, and lab 03 cites lab 02's in-house measurement anchors in the matrix and in the signed decision record. Together the three drills carry the atomic output-shape authoring skills that exercises 01, 05, and 06 depend on, so when the exercises run on the reader's own running system the time goes into engineering judgement — mechanism choice, measurement configuration, vendor evidence — not into inventing the artefact format.
